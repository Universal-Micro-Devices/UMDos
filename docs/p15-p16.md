# P15（SMP）+ P16（AHCI）实现说明（v2.6.112-dev.11）

## 1. P15 SMP

| 模块 | 文件 | 内容 |
|---|---|---|
| 每 CPU 数据 | `src/kernel/percpu.c/h` | `cpu_t`（apic_id / index / stack_top / online / ticks），最多 8 CPU；BSP 栈 8KB（堆分配） |
| 自旋锁 | `src/kernel/spinlock.h` | `spin_lock/unlock`（`__sync_lock_test_and_set`）+ `irq_save/irq_restore`（关中断） |
| MADT | `src/kernel/acpi.c/h` | 解析类型 0（LAPIC）记录，导出 `acpi_lapic_ids()` |
| AP 启动 | `src/kernel/smp.c` | 拷贝跳板到 `0x8000`、信息块 `0x8F00`、LAPIC INIT-SIPI-SIPI、轮询 AP online |
| 跳板 | `src/kernel/smp_tramp.asm` | 16 位实模式 → 32 位保护模式 → 64 位长模式 → 跳 `ap_entry`（内核 PML4） |
| AP 入口 | `smp.c: ap_entry()` | 置 online、打印 `smp: AP online idx=N`、`hlt` 等调度 |
| 全局锁 | `mem.c` / `vfs.c` / `syscall.c` | 内核堆锁（kmalloc/kfree）、VFS 全局锁（系统调用层串行化） |

启动日志：

```
[kernel] percpu: bsp apic_id=0 logical=1
[kernel] smp: madt lapic=2 logical=1
[kernel] smp: BSP only, AP bring-up skipped
[kernel] percpu selftest: bsp/stack/cpuid ok
[kernel] smp selftest: spinlock/bsp ok
```

单核（模拟器）走 BSP 路径；多核 QEMU（`-smp 2`）会执行 INIT-SIPI-SIPI 拉起 AP。
AP 跳板代码已实现但本环境无法验证（unicorn 单核），需在 QEMU `-smp 2` 上确认。

## 2. P16 AHCI

| 模块 | 文件 | 内容 |
|---|---|---|
| PCI | `src/kernel/pci.c/h` | 0xCF8/0xCFC 枚举，类代码 0x01/0x06/0x01，BAR5，使能 memory+bus master |
| AHCI | `src/kernel/ahci.c/h` | HBA 复位（GHC.AE/HR）、端口选择（PI）、命令列表/FIS/PRDT、IDENTIFY(0xEC)、READ DMA EXT(0x25)、WRITE DMA EXT(0x35)，轮询 PxIS 完成 |
| 块设备 | `src/kernel/dev.c` | 识别到 SATA 盘时注册 `ahci` 块设备；`ata` 仍保留作为回退 |
| 启动 | `src/kernel/kmain.c` | `ahci_init()` + `ahci_selftest()` 在 `storage_init()` 之后 |

启动日志：

```
[kernel] ahci: model="UMDos Virtual SATA" sectors=2880 read ok
[kernel] dev: registered serial/kbd/mouse/ahci/ata
```

无 AHCI 控制器时打印 `[kernel] ahci: not found, ATA PIO fallback`，文件系统仍走 ATA PIO。

## 3. 模拟器支持（tools/emu_ui.py）

* PCI 配置空间：端口 0xCF8/0xCFC，返回 `8086:2922`、class `010601`、BAR5 `0xFE000000`；
* AHCI MMIO（0xFE000000，8KB）：CAP/GHC/PI/VS + 端口 0 寄存器；
* 命令执行：解析命令列表/FIS/PRDT，支持 IDENTIFY / READ / WRITE，数据直接读写 `self.img`；
* 完成信号：写入 PxCI 时执行命令并置 PxIS bit3，供驱动轮询（避免内存写回顺序问题）。

## 4. 内存布局调整

AHCI 驱动加入后内核 `.bss` 增长，原 FS 镜像地址 `0x40000` 被覆盖（启动时挂载失败）。
本次把 FS 镜像整体移到 **0x80000**：

* `loader.asm`：`FS_SEG = 0x8000`（第二段 `0x90000`）；
* `kmain.c`：`fs_mount((void *)0x80000, ...)`；
* `ui.c`：`FS_ADDR = 0x80000`。

## 6. 已知限制

1. AP 启动跳板与 INIT-SIPI-SIPI 仅代码实现，unicorn 单核环境无法验证；需 QEMU `-smp 2`。
2. 调度器仍只把内核线程放在 BSP；AP 起来后进入 `hlt`，尚未接收任务（P15 的"AP 跑内核线程"下一版补）。
3. AHCI 驱动为轮询模式，无 NCQ/中断；只处理第一个实现的端口。
4. AHCI 验证基于模拟控制器（非真实 hardware）。
