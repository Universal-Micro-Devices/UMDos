# P3 / P4 实现说明（v2.6.112-dev.3）

## P3：IDT、异常与中断

### 1. IDT

* `src/kernel/idt.c`：64 项 IDT，0–31 异常 + 32–47 硬件 IRQ 全部使用中断门
  （type `0x8E`，选择子 `0x08`），`lidt` 装载。
* 调试约定：IDT 基址写入 `bootinfo + 108`（`0x706C`），供测试工具模拟中断投递
  ——Unicorn 不跟踪 IDTR，无法从 CPU 状态反查。

### 2. 入口桩与分发

* `src/kernel/isr.asm`：48 个入口桩，统一压入向量号与错误码（无错误码补 0），
  保存 15 个通用寄存器后调用 `isr_dispatch(vec, err, rip, cs, rflags)`，返回后
  恢复寄存器并 `iretq`。
* 栈布局（从低到高）：rax..r15（120B）、vector、error、RIP、CS、RFLAGS。
* `isr_dispatch`：`vec < 32` 走异常 → panic 屏；否则 `irq_dispatch(vec - 32)`。

### 3. panic

* 红色整屏，打印异常名（`#DE`/`#GP`/`#PF`…）、error、CS、RIP、CR2、RFLAGS，
  同时把这些信息写串口；之后 `cli; hlt` 死循环，**不重启**。
* 触发方式：任何异常；另提供调试热键 `F9`（`int3`）用于演示 panic 屏。

### 4. PIC / PIT / IRQ

* `src/kernel/irq.c`：PIC 重映射到 `0x20 / 0x28`；只打开 IRQ0（PIT）、IRQ1（键盘）、
  IRQ2（级联）、IRQ12（鼠标）、IRQ14（ATA）。PIT 通道 0 设为 100Hz，中断里累加 tick。
* IRQ1/IRQ12 读取 `0x60` 后推进 `input.c` 的环形缓冲；IRQ14 读状态并计数
  （ATA 驱动本版本仍是 PIO 轮询，IRQ 只做登记）。
* `irq_selftest()`：不依赖真实硬件，直接调用处理逻辑——推进一次 tick、推入扫描码 `0x1E`
  并确认输入层能取到 `'a'` 事件；结果写串口。

### 5. 键盘/鼠标输入双路径

* IRQ 路径：IRQ1/IRQ12 把字节推进环形缓冲，`input_poll` 消费。
* 轮询回退：只要还没有任何 IRQ 到来（模拟器没有 PIC/PIT 硬件模型），
  `input_poll` 直接读 8042；两条路径共用同一套扫描码翻译与鼠标组包。

## P4：物理内存、页帧、堆与页表

* **E820**：loader 用 `INT 15h, EAX=0xE820` 采集最多 32 条，写在 `0x7800`
  （前 4 字节条目数，之后每 24 字节一条），bootinfo 记录地址（`+100`）与数量（`+104`）。
* **页帧分配器**（`src/kernel/mem.c`）：4KB 页，最多管理 128MB（位图 4KB）；
  E820 可用区先标空闲，再预留低 1MB（含 16 位阶段、页表、bootinfo、内核镜像、UMDFS、栈）；
  `pmm_alloc()` 返回清零的物理页，`pmm_free()` 归还。
* **内核堆**：从空闲页里连续划出 1MB 作为堆，`kmalloc/kfree` 首次适配 + 空闲链表
  （暂不合并相邻块，已在 README 已知限制中说明）。
* **页表**：`vmm_map_page/vmm_unmap_page` 按 PML4→PDPT→PD→PT 逐级建表（缺表用 `pmm_alloc`），
  供用户地址空间 `USER_BASE = 0x0000008000000000` 使用；低端 0–4GB 的 2MB 大页恒等映射
  由 head 建立，保持不变。
* **自检**：开机跑 `mem_selftest()`：`kmalloc` 两块、写读校验、`kfree`；
  再把 `USER_BASE` 映射到新页、写读、解映射、`pmm_free`。结果写串口。

## 验收

```sh
python tools/test_p3p4.py
```

覆盖：串口里的 IDT/PIC/PIT/IRQ 自检、E820/页帧/堆/页表自检、登录、
`F9 → int3 → IDT → panic 屏`、以及把 IRQ1 通过真实 IDT 门投递到键盘处理程序。

模拟器限制：Unicorn 不模拟 PIC/PIT，也不跟踪 IDTR。测试工具用内核公开的
IDT 基址手工压中断帧来投递中断，因此验证的是真实的 IDT + 入口桩 + 分发 + 处理逻辑，
但不覆盖 PIC 硬件时序。
