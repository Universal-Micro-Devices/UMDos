# P7 / P8 实现说明（v2.6.112-dev.5）

## P7：VFS 与文件描述符

### 1. 结构

```
用户态 syscall ──> syscall.c ──> vfs.c ──┬── fs.c（UMDFS，目录项 + 块）
                                          └── dev.c（/dev 设备）
```

* `src/kernel/vfs.h` / `vfs.c`：32 个 fd 的表、路径解析、读写、`stat`、`readdir`、`/dev` 路由。
* 每个 fd 记录：类型（FILE / DIR / DEV）、路径、父目录索引、目录项索引、偏移、标志、设备指针。
* 路径解析：以 `/` 开头，逐段用 `fs_set_dir` + `fs_find` 查找，解析前后恢复当前目录；
  支持 `/`、`/CONFIG`、`/CONFIG/AUTH`、`/dev/serial` 等。
* 标准流：fd 0 = `/dev/kbd`，fd 1 / 2 = `/dev/serial`（控制台）。
* 文件写入：读旧内容 + 打补丁 + 整文件写回（上限 4KB），真正的块级增量写留到 P9–P10。
* `O_CREAT` 会在父目录里建空文件；`O_TRUNC` 会先清空。

### 2. 认证改为走 VFS

`auth.c` 不再直接操作 `fs_*`，改为 `vfs_open("/config/auth")` + `vfs_read`，
与安装引导写入的文件格式（`sha3-256$盐$哈希`）统一。

### 3. 系统调用接入 fd 表

`write(fd, buf, len)`、`read(fd, buf, len)`、`open(path, flags)`、`close(fd)`
全部经 VFS；用户指针做 `USER_BASE..USER_LIMIT` 上界检查，路径字符串先拷进内核缓冲区。

## P8：设备模型与驱动框架

* `src/kernel/dev.h` / `dev.c`：设备注册表（最多 8 个），每个设备有名字、类型
  （字符/块）、IRQ、`open/read/write` 回调与收发字节计数。
* 内置设备：
  | 设备 | 类型 | 说明 |
  |---|---|---|
  | `serial` | 字符 | 写 → COM1；读为空 |
  | `kbd` | 字符 | `read()` 取 `input_event`（过滤 EV_KEY） |
  | `mouse` | 字符 | `read()` 取 `input_event`（过滤 EV_MOUSE） |
  | `ata` | 块 | 按 512 字节扇区读 |
* 输入事件化：IRQ1/IRQ12 把字节推进 `input.c` 环形缓冲，设备层 `read()` 把事件转成字节流；
  没有事件时返回 0（非阻塞），UI 仍可直接用 `input_poll`。
* `/dev` 是 VFS 的虚拟目录：`vfs_readdir("/dev", i, ...)` 枚举已注册设备，
  `open("/dev/serial", O_WRONLY)` 直接走设备回调。

## 自检

内核启动时 `vfs_selftest()` 覆盖六项：

1. 读 `/config/auth` 且包含 `sha3-256$`；
2. 写 `/dev/serial`（出现 `[kernel] vfs: /dev/serial write ok`）；
3. `vfs_stat("/config")` 返回目录；
4. 根目录 `readdir` 数量 ≥ 5；
5. `/dev` 虚拟目录数量 ≥ 4；
6. 创建 `/VFSTEST.TXT` → 写 → 读 → 删除。

用户态（模拟器下为等价的内核自检）再通过 `int 0x80` 走一遍
`open("/config/auth") → read → close`，串口打印
`selftest flags: code/write/pid/guard/vfs=11111`。

## 已知限制

1. 文件写入是“整文件重写”，上限 4KB，没有块级增量写与事务。
2. 每个任务没有独立的 fd 表（当前只有演示程序，全局表够用，P9 再按进程拆分）。
3. `/dev` 目录不支持 `open` 后 `readdir` 的组合，只支持直接枚举。
4. 没有权限位、没有符号链接、没有挂载点链表（目前只有 UMDFS 一个文件系统）。
5. ATA 设备只实现了单扇区读。
