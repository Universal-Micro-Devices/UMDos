# P9 / P10 实现说明（v2.6.112-dev.6）

## P9：UMDFS 重构

### 1. 新格式 FS02（带校验和）

超级块在原有字段后新增两个 32 位字段：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 36 | `magic2` | `'FS01'` = 旧格式（无校验）；`'FS02'` = 新格式 |
| 40 | `checksum` | FNV-1a 32 位 |
| 44 | `journal_off` | 日志区偏移（0 表示无） |

校验范围：**超级块前 40 字节 + 目录项表 + 块位图**（`fsgen.py` 与内核用同一算法）。

* 挂载时若 `magic2 == FS02` 且校验不匹配 → **只读挂载**（串口打印
  `fs: checksum mismatch, mounted read-only`），写操作返回 -5。
* 旧格式 FS01 仍然可挂载（向后兼容），不做校验。

### 2. 事务日志（redo）

日志区固定在块 0 偏移 64 处：

```c
typedef struct { u32 magic; u32 entry; u32 valid; u32 crc; u8 bytes[64]; } journal_t;
```

写路径：`journal_record(idx, 新目录项)` → 修改目录项/数据 → `fs_commit()`
（清除 valid 并重算校验和）。挂载时如果发现 `valid` 且 CRC 正确的记录，
就把 `bytes` 重放到对应目录项（**redo**），从而保证“写到一半掉电”后目录项不会半新半旧。

### 3. 增量写 `fs_write_at(name, off, data, len)`

* 容量足够：直接写到 `block_ptr(first_block) + off`，**不重写文件**；
* 容量不足：先尝试在 `first_block + 已用块` 之后**原地扩展**（要求后续块连续空闲）；
* 扩展失败：分配新的连续区、搬运旧数据、释放旧区。

### 4. 自检 `fs_selftest()`

```
[kernel] fs selftest flags: ck=1 rw=11 jrnl=1 data=1 checksum/journal/write_at ok
```

覆盖：校验和、`fs_write` + `fs_write_at`（写 "hello" 再追加 " vfs" 读回）、
日志记录与重放。

## P10：进程抽象与 /proc

### 1. PCB 与每进程 fd 表

```c
typedef struct {
    int  used; u32 pid; u32 ppid; char name[16];
    int  state; int exit_code;
    vfs_fdset_t *fds;        /* kmalloc 出来的每进程 fd 表 */
} proc_t;
```

* 0 号进程是内核本身，`proc_init()` 注册；演示线程挂在它下面。
* `vfs.h` 新增 `vfs_fdset_t` 与 `vfs_current_set()/vfs_select_set()`，
  VFS 的所有 fd 操作都走“当前进程的 fd 表”；内核上下文默认用内核表。
* `proc_spawn()` 分配 PCB + `kmalloc` 一份 fd 表并**复制父进程的 fd**。
* `proc_fork()` = `proc_spawn` 克隆 + 打印新 pid，子进程进入 **READY**。

### 2. /proc 只读虚拟文件系统

VFS 在 `open` 时识别 `/proc/<name>`，用 `kmalloc(512)` 生成内容：

| 路径 | 内容 |
|---|---|
| `/proc/version` | UMDos 版本与内核阶段 |
| `/proc/meminfo` | 页帧总数/空闲、堆大小 |
| `/proc/tasks` | PID/PPID/状态/名字（含 fork 出的子进程） |
| `/proc/mounts` | umdfs / proc / devfs 挂载点 |

`readdir("/proc")` 返回这四个名字；`read` 从生成的缓冲区按偏移返回。

### 3. 系统调用

新增 `SYS_fork`（=8）、`SYS_exec`（=9，占位 -1）、`SYS_getppid`（=10）；
`fork` 直接调用 `proc_fork()`。

### 4. 自检 `proc_selftest()`

```
[kernel] proc selftest: fork/fd/tasks/proc ok (fork_ok=1 tasks=1 fds=1 proc=1)
```

覆盖：fork 成功且进程数 +1、`/proc/tasks` 文本里能找到子 pid、
子进程 fd 表已复制（fd 0 打开）、四个 /proc 生成函数都有输出。

## 已知限制

1. fork 只克隆 PCB/fd 表，子进程进入 READY 但**用户态抢占调度**留到 P11。
2. 日志一次只记录一个目录项（单条 redo），没有多事务队列。
3. 没有 fsync 语义：数据写完后靠 `fs_flush()` 整盘刷回。
4. `/proc` 内容在 open 时快照，不支持动态刷新。
5. exec 仍是占位：需要从 VFS 读 ELF，P11 实现。
